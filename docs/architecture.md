## 2. Data Model

### 2.1 Raw Capture (`raw/` folder)

Every capture is a plain text file with YAML frontmatter. No database needed — filesystem is the store.

```yaml
---
id: <uuid4>
timestamp: "2026-11-21T03:33:31.000Z"
type: note | link | file
source: manual | cli | url
original_path: /path/to/file.pdf   # only for file type
---

<raw content — plain text, markdown, or extracted text from file>
```

**File naming**: `<timestamp>_<uuid8>.md`
Example: `raw/20261121_033331_a1b2c3d4.md`

### 2.2 Wiki Note (`wiki/` folder)

Enriched version of a raw capture with AI-generated metadata.

```yaml
---
id: <uuid4>
raw_id: <uuid4>               # back-reference to raw/
timestamp: "2026-11-21T03:33:31.000Z"
category: Projects | Areas | Resources | Archives
tags: [python, ai, machine-learning, research]
summary: "One-line summary from LLM"
links_to: [<note_id>, ...]    # auto-detected related note IDs
links_from: [<note_id>, ...]  # reverse links
embedding_ref: embeddings/<id>.npy  # path to vector
---

# <title or first line>

<note content>

## Related
- [[note_id_1]] — similarity: 0.87
- [[note_id_2]] — similarity: 0.81
```

**File naming**: `<timestamp>_<uuid8>.md` in `wiki/<PARA_CATEGORY>/`

### 2.3 Embeddings (`embeddings/` folder)

Each note gets a vector stored as a `.npy` file keyed by note ID.

```
embeddings/
  <note_id>.npy    # 384-dim vector (sentence-transformers all-MiniLM-L6-v2)
```

A master index maps note IDs to file paths:
```
embeddings/
  index.json       # {"note_id_1": "embeddings/note_id_1.npy", ...}
```

### 2.4 Graph Data (`graph.json`)

Generated by `build_graph.py`. Static JSON file consumed by the frontend.

```json
{
  "nodes": [
    {
      "id": "<note_id>",
      "label": "<title/summary>",
      "category": "Projects",
      "tags": ["python", "ai"],
      "summary": "...",
      "degree": 3,
      "group": "Projects",
      "content_preview": "first 200 chars of content"
    }
  ],
  "edges": [
    {
      "from": "<note_id_a>",
      "to": "<note_id_b>",
      "weight": 0.87,
      "label": "0.87 similarity"
    }
  ],
  "meta": {
    "total_nodes": 42,
    "total_edges": 87,
    "categories": ["Projects", "Areas", "Resources", "Archives"],
    "generated_at": "2026-11-21T03:33:31.000Z"
  }
}
```

## 3. Module Architecture

### 3.1 `capture.py` — The Archivist (Week 1)

**Responsibility**: One command saves any note, link, or file to `raw/` with timestamp + unique ID.

```
CLI:
  python capture.py --note "My quick thought"     # text note
  python capture.py --link https://example.com    # URL capture
  python capture.py --file /path/to/doc.pdf       # file capture
  python capture.py --stdin                       # pipe input
```

**Internal flow**:
```
1. Generate UUID + timestamp
2. Detect input type (note / link / file)
3. If link: fetch page title + content via requests/BeautifulSoup
4. If file: extract text (PyPDF2 for PDFs, python-docx for DOCX, raw text for .md/.txt)
5. Write to raw/ with YAML frontmatter
6. Print confirmation with ID + path
```

**Dependencies**: `uuid`, `datetime`, `requests`, `beautifulsoup4`, `PyPDF2`, `python-docx`, `pathlib`

**Config**: `RAW_DIR` constant = `"raw/"` (configurable via env var `SECON DSELF_RAW_DIR`)

### 3.2 `classify.py` — The Sorting Hat (Week 2.1)

**Responsibility**: Send each raw capture to Groq LLM → get PARA category, tags, and one-line summary. Write enriched notes to `wiki/`.

```
CLI:
  python classify.py                    # process all unprocessed raw/
  python classify.py --id <uuid>        # process one capture
```

**Internal flow per capture**:
```
1. Read raw/ capture (frontmatter + content)
2. Build LLM prompt:
   - System: "You are a knowledge organizer. Classify into PARA..."
   - User: <capture content>
   - Response format: JSON { category, tags[], summary }
3. Call Groq API (llama3-70b-8192 or mixtral-8x7b-32768)
4. Parse JSON response
5. Create wiki/ note:
   - Copy content from raw/
   - Add AI metadata to frontmatter
   - Place in wiki/<category>/
6. Delete or archive raw/ capture (mark as processed)
```

**LLM Prompt Template**:
```
You are a personal knowledge organizer. Given a note, classify it.

Return ONLY a JSON object:
{
  "category": "Projects" | "Areas" | "Resources" | "Archives",
  "tags": ["tag1", "tag2", "tag3"],
  "summary": "one-line summary (max 80 chars)"
}

Note content:
<content>

Rules:
- Projects: specific tasks with deadline/goal (e.g., "build portfolio", "launch startup")
- Areas: ongoing responsibilities (e.g., "health", "team management", "finances")
- Resources: reference material (e.g., "React docs", "design inspiration")
- Archives: inactive/completed items
```

**Dependencies**: `groq` (or `requests` for direct API), `json`, `pathlib`

**Env vars**: `GROQ_API_KEY`

### 3.3 `link.py` — Connect the Dots (Week 2.2)

**Responsibility**: Compute embeddings for every note, compare pairwise, auto-insert links above similarity threshold.

```
CLI:
  python link.py                        # process all unlinked notes in wiki/
  python link.py --rebuild              # recompute all embeddings + links
  python link.py --threshold 0.75       # override default threshold
```

**Internal flow**:
```
1. For each wiki/ note without embedding:
   a. Load note content
   b. Generate embedding via sentence-transformers (all-MiniLM-L6-v2, 384 dims)
   c. Save to embeddings/<note_id>.npy
2. For each new note embedding:
   a. Load all existing note embeddings into matrix
   b. Compute cosine similarity vs all other notes
   c. For each similarity > threshold (default 0.75):
      - Add note_id to this note's links_to[]
      - Add reverse link to target note's links_from[]
   d. Save updated wiki/ notes
3. Print summary: "N notes processed, M links created"
```

**Embedding model**: `sentence-transformers/all-MiniLM-L6-v2`
- 384-dimensional vectors
- Local + free (no API key needed)
- Fast CPU inference (~10ms/note)

**Similarity threshold**: 0.75 default (configurable)
- Cosine similarity: `1 - cosine_distance(embedding_a, embedding_b)`
- 0.75 = strong semantic relationship
- 0.60–0.74 = weak relationship (logged but not linked)

**Dependencies**: `sentence-transformers`, `numpy`, `scikit-learn` (cosine_similarity), `pathlib`

### 3.4 `build_graph.py` — Give It a Shape (Week 3.1)

**Responsibility**: Read all wiki/ notes + their links → build nodes/edges JSON → export to `graph.json`.

```
CLI:
  python build_graph.py                  # build graph.json from wiki/
  python build_graph.py --output graph.json
```

**Internal flow**:
```
1. Walk wiki/ recursively, collect all .md files
2. Parse frontmatter of each note:
   - Extract: id, title, category, tags, summary, links_to
   - Compute degree (number of links)
3. Build nodes array:
   - id, label (title or first line), category, tags, summary, degree, group
4. Build edges array:
   - For each note's links_to[], create {from, to, weight, label}
   - Deduplicate (undirected: edge A→B = edge B→A)
5. Compute category colors for visualization
6. Write graph.json
```

**Node schema**:
| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Note UUID |
| `label` | string | Title or first line |
| `category` | string | PARA category |
| `tags` | string[] | AI-generated tags |
| `summary` | string | AI one-liner |
| `degree` | int | Number of connections |
| `group` | string | Category (for coloring) |
| `content_preview` | string | First 200 chars |

**Edge schema**:
| Field | Type | Description |
|-------|------|-------------|
| `from` | string | Source note ID |
| `to` | string | Target note ID |
| `weight` | float | Similarity score (0–1) |
| `label` | string | Display label |

**Dependencies**: `json`, `pathlib`, `re` (for parsing)

### 3.5 `ask.py` — Ask Your Brain (Week 4.1)

**Responsibility**: `ask(question: str) -> str` — retrieval-augmented Q&A over your notes.

```
CLI:
  python ask.py "What are my current projects?"
  python ask.py --interactive
```

**Internal flow**:
```
1. User submits question string
2. Generate question embedding (same sentence-transformers model)
3. Load all note embeddings into matrix
4. Compute cosine similarity: question vs all notes
5. Retrieve top-K (default 5) most relevant notes above min_threshold (0.5)
6. Build LLM prompt:
   - System: "You are SecondSelf. Answer using ONLY the provided context..."
   - Context: concatenated relevant note contents + summaries
   - User: question
7. Call Groq LLM with context
8. Return answer + source citations (which notes were used)
```

**LLM Prompt Template**:
```
You are SecondSelf, a personal knowledge assistant.
Answer the question using ONLY the provided context from the user's notes.
If the context doesn't contain relevant information, say so.

Context (relevant notes):
---
[Note 1: <title>]
<content>
---
[Note 2: <title>]
<content>
---

Question: <question>

Answer concisely. Cite which notes you used by their title.
```

**Return format**:
```python
{
  "answer": "Your current projects are: A, B, and C. Based on notes...",
  "sources": [
    {"id": "uuid", "title": "Project A", "similarity": 0.92},
    {"id": "uuid", "title": "Project B", "similarity": 0.85}
  ],
  "query_embedding_time_ms": 12,
  "llm_time_ms": 1400
}
```

**Dependencies**: `sentence-transformers`, `numpy`, `scikit-learn`, `groq` (or `requests`)

## 4. Data Flow

### 4.1 Capture → Classification → Linking

```
User: python capture.py --note "Learning React hooks"
 │
 ├──▶ raw/20261121_033331_a1b2c3d4.md
 │     frontmatter: id, timestamp, type=note
 │     body: "Learning React hooks"
 │
User: python classify.py
 │
 ├──▶ Reads raw/20261121_033331_a1b2c3d4.md
 ├──▶ Calls Groq LLM → { category: "Resources", tags: ["react", "hooks"], summary: "Learning React hooks fundamentals" }
 │
 ├──▶ Creates wiki/Resources/20261121_033331_a1b2c3d4.md
 │     frontmatter: id, raw_id, category=Resources, tags, summary, links_to=[]
 │     body: "Learning React hooks"
 │
User: python link.py
 │
 ├──▶ Embeds "Learning React hooks" → embeddings/a1b2c3d4.npy
 ├──▶ Compares with all existing wiki/ note embeddings
 ├──▶ Finds match: "useEffect vs useLayoutEffect" (sim=0.82)
 │
 ├──▶ Updates both wiki/ notes:
 │     Note A links_to: [note_b_id]
 │     Note B links_from: [note_a_id]
 │
User: python build_graph.py
 │
 └──▶ graph.json: { nodes: [..., note_a, note_b, ...], edges: [..., {from: note_a, to: note_b, weight: 0.82}, ...] }
```

### 4.2 Ask Flow

```
User: app.py → "What React topics have I been studying?"
 │
 ├──▶ ask("What React topics have I been studying?")
 │     ├──▶ embed(question) → [0.12, -0.03, 0.89, ...]
 │     ├──▶ Load all embeddings from embeddings/*.npy
 │     ├──▶ cosine_similarity(question_emb, all_notes) → top 5:
 │     │     note_1: "Learning React hooks" (0.91)
 │     │     note_2: "useEffect vs useLayoutEffect" (0.87)
 │     │     note_3: "React state management" (0.72)
 │     ├──▶ Build LLM prompt with top-3 note contents as context
 │     ├──▶ Call Groq LLM → synthesized answer
 │     └──▶ Return { answer, sources }
 │
 └──▶ Display answer in UI with source note cards below
```

## 10. Error Handling & Edge Cases

| Scenario | Strategy |
|----------|----------|
| Groq API rate limit / outage | Retry with exponential backoff (3 attempts). Fallback to `llama3-8b-8192` if 70b fails. |
| Embedding model download (first run) | sentence-transformers downloads on first use (~90MB). Show progress in Streamlit. |
| Empty wiki/ (no notes yet) | `build_graph.py` outputs empty graph. `ask.py` returns "No notes found." |
| File too large (>10MB PDF) | Skip with warning. Truncate content to first 50KB. |
| URL fetch fails | Save raw URL as-is with `type: link` and empty body. LLM can still classify from title. |
| No GROQ_API_KEY set | `classify.py` and `ask.py` fail with clear error message + setup instructions. |
| Duplicate captures (same URL) | Check `raw/` for existing URL. Skip or create new with "duplicate" tag. |
| Very similar notes (>0.95) | Deduplicate: merge into single note, keep newer version. |
| No notes above similarity threshold | Graph shows isolated nodes. Ask() returns "No relevant notes found." |

## 12. Design Decisions & Rationale

| Decision | Rationale |
|----------|-----------|
| **File-based storage (no DB)** | No database to set up, debug, or migrate. Markdown files are human-readable, git-friendly, and portable. For a personal knowledge base (hundreds of notes), filesystem is fast enough. |
| **YAML frontmatter** | Keeps metadata + content in one file. Easy to parse, edit, and version. |
| **sentence-transformers (local)** | Free, runs on CPU, no API limits. all-MiniLM-L6-v2 is 384-dim, ~90MB, fast inference. |
| **Groq (cloud LLM)** | Free tier is generous, fast inference (~500 tokens/sec), good model selection. No need to run models locally. |
| **Streamlit** | Fastest way to build a data/visualization app in Python. Built-in component model + easy deployment. |
| **vis-network.js** | Force-directed physics, built-in hover/zoom/drag, good looking by default, well-documented. |
| **Markdown + YAML (not JSON)** | Human-readable, editable, git-diffable. The wiki/ folder IS the database. |
| **Embeddings as .npy files** | Fast NumPy load/save, no database overhead, easy to backup/move. |
| **No vector database** | For personal scale (<1000 notes), brute-force cosine similarity in NumPy is faster than setting up Pinecone/Weaviate/Chroma. |
| **LLM for classification, not rules** | PARA classification is nuanced — an LLM understands context better than keyword matching. Free tier Groq is fast enough for batch processing. |
| **Single Streamlit app** | One file for everything: graph + search + browse. Simple to deploy, simple to share. |
| **Capture → Classify → Link (separate steps)** | Each step is independently testable and debuggable. Can re-run any step without re-running others. |
